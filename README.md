# 🤖 P2P Monitor Bot (Wallet + Bybit)

Telegram-бот для мониторинга цен покупки USDT на двух P2P площадках: **[Wallet](https://wallet.tg)** и **[Bybit](https://www.bybit.com/)**.

Мониторит **покупку USDT** (отдаём тенге — KZT — и получаем USDT) на паре **USDT/KZT**, обе площадки опрашиваются параллельно.

## Что умеет

- 📊 **Мониторинг в реальном времени** — проверяет цены каждые N секунд на обеих площадках (Wallet и Bybit) параллельно
- 🎯 **Пороговые алерты** — уведомление, когда цена покупки падает до порога или ниже; алерт приходит от площадки, чья цена достигла порога
- 📏 **Фильтр по лимитам** — учитываются только объявления, чей лимит суммы попадает в заданный диапазон (например 0–500 000 KZT); объявления вроде «1 000 000–5 000 000» не попадают ни в цены, ни в алерты
- 🏆 **Топ объявлений** — лучшие 5 предложений по команде `/top` (по каждой площадке)
- ⏸ **Пауза/Возобновление** — контроль через Telegram (кнопки или команды)
- ⌨️ **Персистентная клавиатура** — основные действия всегда под рукой

## Быстрый старт

### 1. Получи ключи

| Ключ | Где взять |
|------|-----------|
| `BOT_TOKEN` | [@BotFather](https://t.me/BotFather) — создай нового бота |
| `CHAT_ID` | [@userinfobot](https://t.me/userinfobot) — узнай свой ID |
| `WALLET_API_KEY` | Wallet → P2P Маркет → Профиль → API Keys |
| — | **Ключи Bybit не нужны** — используется публичный P2P эндпоинт (совпадает с UI, работает без ключа) |

> Ключи Bybit (`BYBIT_API_KEY`/`BYBIT_API_SECRET`) **не требуются и не используются**. Источник цен — публичный P2P эндпоинт (taker feed), который совпадает с тем, что видно в UI Bybit.

### 2. Настрой окружение

```bash
cp .env.example .env
```

Заполни `.env` своими ключами.

### 3. Установи и запусти

```bash
npm install
npm start
```

## Локальный запуск через Docker

Требуется установленный [Docker](https://www.docker.com/products/docker-desktop/) (Compose v2+).

```bash
# 1. Настрой окружение (если ещё не создан)
cp .env.example .env

# 2. Собери и запусти контейнер
sudo docker compose up -d --build

# 3. Смотри логи
sudo docker compose logs -f

# 4. Остановить
sudo docker compose down
```

- Keep-alive сервер бота доступен на `http://localhost:3000` (healthcheck — `/health`).
- Секреты (`.env`) **не зашиваются в образ** — они подхватываются через `env_file` при запуске контейнера.
- Контейнер перезапускается автоматически при падении (`restart: unless-stopped`).
- Если Docker требует `sudo` на вашей машине — используйте команды с `sudo`, как выше; на macOS с Docker Desktop `sudo` не нужен.
- Чтобы поменять ключи/порог: отредактируй `.env` и перезапусти контейнер (`docker compose up -d`).

## Команды бота

| Команда | Описание |
|---------|----------|
| `/start` | Приветствие и список команд |
| `/help` | Справка |
| `/status` | Текущий статус и статистика |
| `/price` | Мгновенная проверка цены (обе площадки) |
| `/top` | Топ-5 лучших объявлений (обе площадки) |
| `/pause` | Приостановить мониторинг |
| `/resume` | Возобновить мониторинг |
| `/set_threshold <цена>` | Установить порог покупки, например `/set_threshold 445` (совместимо: `/set_threshold kzt 445`) |
| `/set_min_limit <KZT>` | Мин. лимит суммы объявления, например `/set_min_limit 10000` (`off` — сброс) |
| `/set_max_limit <KZT>` | Макс. лимит суммы объявления, например `/set_max_limit 500000` (`off` — сброс) |

Помимо команд, доступна персистентная клавиатура с кнопками:
`📊 Статус`, `🔎 Проверить цену`, `🛒 Порог KZT`, `⏸ Пауза`, `▶️ Возобновить`.

## Фильтр по лимитам объявления

- Объявление учитывается в ценах, `/top` и алертах, **только если его диапазон `[minAmount, maxAmount]` пересекается с заданным `[MIN_LIMIT_KZT, MAX_LIMIT_KZT]`**.
- Пример: при `MAX_LIMIT_KZT=500000` объявление с лимитом «1 000 000–5 000 000 KZT» исключается — его минимальная сумма выше бюджета, купить его нельзя, поэтому алерты по нему не приходят.
- Лимиты задаются в `.env` (`MIN_LIMIT_KZT`/`MAX_LIMIT_KZT`) или командами `/set_min_limit`/`/set_max_limit` в Telegram (меняются на лету, без перезапуска).
- Пустые значения = без фильтра. `MIN_LIMIT_KZT=0` — без нижней границы.

## Алерты по порогу

- Алерт приходит, когда **цена покупки ≤ заданного порога** на одной из площадок.
- Порог задаётся кнопкой «🛒 Порог KZT» или командой `/set_threshold` и применяется к обеим площадкам.
- В алерте указано, с какой площадки цена (Wallet или Bybit), плюс продавец, способы оплаты и лимит.
- Если текущая цена уже ниже нового порога, алерт придёт при ближайшей проверке.
- Повторные алерты приходят только при **изменении цены** ниже порога: пока цена не меняется, спама не будет.

## Площадка Bybit

- **Единственный источник — публичный эндпоинт**: `POST https://api2.bybit.com/fiat/otc/item/online` (taker feed). Именно он совпадает с тем, что видно в UI Bybit (проверено вживую: 478.90 = 478.90), и работает **без ключей**.
- **Официальный advertiser-API не используется**: `POST /v5/p2p/item/online` возвращает более широкую книгу с объявлениями по цене ~403 KZT, которых тейдеры в UI не видят (это давало бы ложные алерты). Убран из кода полностью.
- **Только онлайн-объявления**: мониторятся исключительно объявления с `isOnline=true`. Офлайн-объявления (в т.ч. скам-приманки с ценой сильно ниже рынка, которые Bybit не показывает тейдерам в UI) в цены и алерты не попадают.
- **Лимиты**: безопасный интервал опроса — 10–30 секунд (у бота по умолчанию 30). Агрессивный опрос (чаще 1–2 сек) ведёт к блокировке IP (403).

## Деплой на VPS (рекомендуется вместо Render)

> **Почему VPS?** На Render Free сервис засыпает после ~15 минут без запросов. Пока он спит,
> бот не опрашивает Telegram: команды копятся на серверах Telegram и доставляются только после
> пробуждения (а иногда теряются совсем — см. логи «Telegram bot launch failed»). На VPS бот
> работает 24/7, cron-job.org больше не нужен.
>
> 📋 **Пошаговый чеклист дня переезда (Render → VPS): [`deploy/MIGRATION.md`](deploy/MIGRATION.md)**

### Быстрый путь — скрипт `deploy/deploy-vps.sh`

Скрипт сам клонирует/обновляет репо, проверяет Docker, создаёт `.env` из шаблона,
подбирает свободный порт (не конфликтует со вторым проектом) и поднимает контейнер:

```bash
git clone https://github.com/ayan577/p2pmonitoring.git && cd p2pmonitoring
bash deploy/deploy-vps.sh
# с явным портом:  P2P_PORT=4100 bash deploy/deploy-vps.sh
```

Повторный запуск = обновление (`git pull` + пересборка).

### Вариант А — Docker Compose (проще)

```bash
# на VPS
git clone <URL-репозитория> p2p-monitor && cd p2p-monitor
cp .env.example .env
nano .env              # впиши свои BOT_TOKEN / CHAT_ID / WALLET_API_KEY
sudo docker compose up -d --build
sudo docker compose logs -f
```

Обновление: `git pull && sudo docker compose up -d --build`

> **Если порт 3000 занят другим проектом на VPS** — задай другой хост-порт:
> `P2P_PORT=3100 sudo docker compose up -d --build`. Имя контейнера — `p2p-monitor`;
> если оно тоже занято, поменяй `container_name` в `docker-compose.yml`.

### Вариант Б — systemd (без Docker)

```bash
# на VPS, нужен Node.js >= 20
git clone <URL-репозитория> p2p-monitor && cd p2p-monitor
cp .env.example .env
nano .env              # впиши свои ключи
npm ci --omit=dev
```

Готовый юнит лежит в репо — `deploy/p2p-monitor.service`:

```bash
sudo cp deploy/p2p-monitor.service /etc/systemd/system/
sudo nano /etc/systemd/system/p2p-monitor.service   # поправь WorkingDirectory и путь к node (which node)
sudo systemctl daemon-reload
sudo systemctl enable --now p2p-monitor
journalctl -u p2p-monitor -f   # логи
```

### Совместимость с другим проектом на VPS

- **Порт:** Express keep-alive сервер слушает порт из `PORT` в `.env` (по умолчанию 3000).
  Перед запуском проверь, что порт свободен: `ss -tlnp | grep 3000` (или `netstat -tlnp`).
  Если занят — поменяй `PORT` в `.env`, а для Docker ещё и `P2P_PORT` (см. выше).
- **Имя контейнера** `p2p-monitor` должно быть уникальным на хосте: `docker ps -a | grep p2p`.
- **systemd-юнит** `p2p-monitor.service` не пересекается с другими сервисами.
- Бот ходит только наружу (Telegram API + P2P API), никаких файлов/БД не пишет, ресурсов ест мало —
  второму проекту мешать не будет.

> ⚠️ **Перед запуском на VPS останови/удали сервис на Render.** Два процесса, опрашивающих один
> и тот же токен одновременно, конфликтуют (Telegram отвечает 409) — команды перестанут
> обрабатываться. Один и тот же бот может работать только в одном месте.
> Keep-alive Express сервер (/health) на VPS не нужен, но и не мешает.

## Архитектура

```
index.js
├── Express Server (/health, /) — keep-alive для Render
├── Telegraf Bot — обработка команд и кнопок
├── checkPrices() — основной цикл (защита от параллельных запусков)
│   ├── checkPlatformPrice(WALLET) — Wallet P2P API (5 страниц × 50, параллельно)
│   ├── checkPlatformPrice(BYBIT)  — Bybit: публичный эндпоинт (taker feed,
│   │                                совпадает с UI, только онлайн-объявления)
│   ├── analyzeAds() — лучшая/худшая цена, средняя, спред
│   └── sendAlert() — пороговое уведомление в Telegram (с указанием площадки)
└── setInterval — запуск checkPrices каждые N секунд
```
